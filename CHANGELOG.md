# Changelog

Dated entries, newest first. Each entry is a finished unit of work.

## 0.5.0 — 2026-11-08

- The polluter lives here now. `isp_data_pollution.py` is vendored from upstream
  commit `99862ab` with the eight compatibility patches folded in, so the build
  neither clones upstream nor applies a patch series: `patches/` and
  `UPSTREAM_COMMIT` are gone. The series used to fail the build when upstream
  drifted; now there is nothing to drift, and the fixes are ordinary reviewed
  code with a test suite behind them.
- The repository is GPL-3.0-or-later, the license the vendored script carries.
  Upstream's repository ships an MIT `LICENSE` for the same file while the file
  header says GPL-3.0-or-later, so the more restrictive reading is taken; the
  MIT text is kept at `LICENSES/UPSTREAM-MIT.txt` and `NOTICE` carries the
  attribution.
- Owning the file meant fixing it rather than patching around it, and no file is
  exempted from lint or type checking. Some of the findings were live bugs:
  `from pyvirtualdisplay import Display` never resolved, so the optional Xvfb
  path had been dead code since it was written (it now imports the real module,
  starts only when `Xvfb` exists, and warns instead of dying if a display
  cannot be had); the link harvesters closed over loop variables, so a deferred
  read could act on a later element; `pid`, `rss_mb`, `current_url` and `uap`
  were read on paths where they had never been assigned; `set_url()` was handed
  bytes; and an unparsable chromedriver version string stopped startup over a
  check that only prints advice.
- Every `urlopen()` goes through `open_http()`, which refuses any scheme but
  http(s). Scraped pages and blacklist feeds supply most of those URLs, so a
  `file:` target would have been a local file read driven by remote content.
- Dependencies moved to `uv`: `pyproject.toml` plus a committed `uv.lock`, no
  `requirements.txt`, and the image installs the same lock the tests run
  (`uv sync --frozen`), which also takes `py3-pip` out of the build.
- Tests exist. `tests/test_units.py` covers environment parsing, seed word
  validation, http(s)-only link filtering, per-domain caps, the heartbeat file
  and the seeding cooldown without a browser or network. `tools/smoke_test.sh`
  builds the image, runs it, and proves it is generating traffic: a detached
  container prints almost nothing, because the per-page progress lines need a
  terminal, so the test watches the health file instead — measured 1.6 MB in
  60 s at `GBPM=500` with a fresh health stamp and no tracebacks. CI runs lint,
  types, unit tests, the image build, and that smoke test.

## 0.4.2 — 2026-11-08

- A bot-walled seeding search no longer eats the pollute loop. The engines
  headless traffic is bot-walled, and while the link library is thin `pollute()`
  buys a seeding search on every iteration — paying a chromedriver hang and a
  driver restart before reaching the page it already had. A search that takes
  longer than `SEED_SEARCH_BUDGET` (20 s) now pauses further searching for
  `SEED_SEARCH_COOLDOWN` (300 s) and pollution continues from the library
  (`patches/0008-seeding-search-budget.patch`); both knobs are validated at
  startup like the rest.
- Throughput against `0.4.1`, both containers on the same network for the same
  10 minutes at `GBPM=500`: page loads 5.8/min → 13.9/min, data polluted
  2.1 MB/min → 8.3 MB/min, chromedriver hangs 18 → 4, domain entropy 3.0 →
  4.9 bits. A 25-minute run held 66-83 pages per 5 minutes, grew the link
  library from 3.4k to 13.7k links, and averaged 5.7 bits of domain entropy —
  past warm-up the library stays above the seeding threshold, so searching is
  barely needed at all.

## 0.4.1 — 2026-11-08

- Search seeding has a word list again. The dictionary URL the upstream script
  fetches no longer returns words to this client — a plain HTTP client gets 404,
  a browser-user-agent client gets a bot-challenge page — and every line of
  whatever came back became a search term, so the seeder was querying minified
  JavaScript. Seed words now come from a vendored MIT frequency list
  (`seedwords/seed-words.txt`, regenerated by `tools/refresh_seedwords.sh`) read
  through `SEED_WORDS_FILE`, and a remotely fetched list is rejected unless it is
  word-shaped (`patches/0007-seed-word-list.patch`).
- Throughput against `0.4.0`, both containers on the same network for the same
  10 minutes at `GBPM=500`: page loads 6/min → 17/min, data polluted
  1.6 MB/min → 4.0 MB/min, chromedriver hangs 1.9/min → 1.3/min.

## 0.4.0 — 2026-11-08

- The container runs again. The Shalla blocklist this image downloaded is gone
  (Shalla Secure Services shut down; the URL returns 404) and one dead EasyList
  URL took the whole download loop with it, so every start exited with
  `Empty blacklists! Exiting.`
- `BLACKLIST=off|local|remote` selects the link filter: `local` is now the
  default and reads a vendored MIT list of ~78 000 ad, tracker, and malware
  domains baked into the image, so no third-party list is needed at runtime.
  `tools/refresh_blocklist.sh` regenerates it with its provenance header.
- Runtime modernised to alpine 3.24: CPython 3.14, Chromium/chromedriver 156,
  selenium 4.52, numpy 2.5, fake-useragent 2.2. Dependencies install into a
  virtualenv because modern Alpine Python is marked externally managed.
  Domain entropy per page improved from ~1.1 to ~2.0 bits against the previous
  base, because the old Chromium no longer renders current sites.
- Removed `linux/arm/v7`. Alpine stopped building Chromium for armv7 after
  3.11 (Chromium 80), so the 3.24 base has no `chromium` package there and the
  multi-arch build died at `apk add`. The platform was already unusable: no
  Chromium released for 32-bit ARM since 2020 renders current search pages.
- Compatibility fixes upstream never made, applied as a patch series that fails
  the build when a patch stops matching: Selenium 4 element lookup and driver
  service, `browserVersion` capability, numpy 2 scalar conversions,
  `random.sample()` on sets (removed in Python 3.11), explicit
  `importlib.util`, and keeping non-http targets out of the link library.
- `HEALTHCHECK` reports `unhealthy` when the pollute loop stops making progress
  instead of leaving a stuck container looking idle.
- Base image, upstream script, and patches are pinned and verified at build
  time: the upstream script is cloned at a commit and patched with `git apply`
  instead of `sed`, which used to succeed while matching nothing.
- Default `MEM` raised 512 → 2048 MB: the chromedriver memory watchdog was
  tuned for Chromium 80 and restarted the driver constantly on current pages.
- CI fixed: both workflows ran on the retired `ubuntu-20.04` runner, so nothing
  had run in years. They now build on `ubuntu-latest` with layer caching, on
  pull requests as well as pushes, and releases can be rebuilt manually.
- Invalid configuration (`BLACKLIST`, `GBPM`, `MEM`, `CHROMEDRIVER_PATH`) is
  rejected at startup with a message instead of surfacing deep inside the script.
- Added `LICENSE` (MIT), `NOTICE` with upstream and blocklist attribution, and
  the upstream license text inside the image. The Shalla lists are explicitly
  not redistributable and are not shipped.
